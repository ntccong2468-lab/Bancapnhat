## Business paths checked

- **Paid KIZ and existing stock:** the new paid-only guard reads rich permit validity at both print-proof and coordinator prerequisite boundaries. The public physical identity resolver and shared `currentObservation` rule are unchanged. Existing stock/imported stock keeps its identity. Accepted unpublished registrations retain their native/feed ownership; a changed Catalog key temporarily requires fresh paired sources before a new paid request. Existing paid/ambiguous purchases are still resolved before new-order prerequisites, preserving idempotent resume.
- **Document projection:** only active observed permits reach flattened products; explicit invalid/unresolved/count evidence clears stale flattened permit fields, while absent observations retain legacy documents. Rich expiry/status evidence remains in the Catalog cache. The public projection now validates the supplied observation epoch and holds the same local epoch lock across upsert/restore/document writes, so a late old-key projection cannot overwrite a newer product or declaration.
- **Native mapping:** WB mapping requires the same nonempty normalized article plus the existing owner, age, publication, trade-unit, complete colour set, size and duplicate checks. Empty/unusable GTIN barcodes produce per-variant issues. Ambiguity counts only fully eligible cards. Ozon's separately reviewed matching rules remain intact.
- **WB review and completion:** a ready Catalog receipt no longer avoids the fresh WB read before matching. Cached `046` completion affects only an unsubmitted WB report. The transaction checks owner/run kind, exact native keys, original GTIN/state/timestamp, no child journal and current native barcode. Existing children/terminal rows are excluded. Previous candidate source/feed/publication/approval evidence is removed; no Catalog mapping, registration pointer or paid proof is created from `046` presence.
- **Feed identity:** an explicitly foreign `feed_id` is rejected before its status/errors or card fallback can advance or reject the saved request. Matching IDs and legacy responses without an explicit ID keep their prior semantics.
- **Catalog credential rotation:** credential digest and opaque UUID read epoch change atomically. Rechecking the same key retains the epoch; rotation/removal and A→B→A cannot revive an old epoch. The physical `RegisteredGtinProof.source`, seller/certificate identities, feeds, jobs and stock remain independent of this read epoch.
- **Source freshness:** the successful paired WB/Catalog receipt is the only path that marks the current epoch complete. A Catalog-only read cannot restore new-write proof. Initial connection discovery happens before successful epoch capture; a preparation failure records a failed source attempt while historical display membership remains available. Both ordinary and version-index read cursors include the captured epoch and cannot resume or clear another epoch's scan.
- **Crash recovery:** readiness also requires the completed epoch marker. A process crash after committing a successful paired receipt but before committing that marker therefore leaves readiness blocked, historical display available, and the next GTIN review on the paired WB/Catalog refresh path. The added regression deletes only that marker after a real synthetic paired success and proves both sources are read to recover it; the WB-only branch fails the test. Legacy empty-epoch behavior remains compatible.
- **Old workers and snapshots:** clients, short caches, in-flight reads and joined subscribers retain/check their captured epoch. Real observations carry a separate optional `RegisteredGtin.readRevision`, outside physical Catalog details. Common repository checks run inside the SQLite transaction before full replacement or merge. An immutable result envelope also protects an empty full read. Empty merge/projection remains a no-op. Old JSON defaults to the legacy empty epoch. Physical content equality and GTIN-evidence hashes exclude the read epoch.
- **Direct publication:** `ObservedCard` carries the original client's epoch, with legacy constructors retained and a post-read scope assertion. Ozon's direct existing-card link/publication writers check the captured epoch inside the same transaction before native or cache changes. Pending-document preservation keeps this stamp. A late old/ABA observation cannot overwrite current proof or alter the saved publication checkpoint.
- **Diagnostics and documentation:** exact GTIN/permit/source reasons use the intended localized keys. Shared conflict advice no longer directs every WB seller to Ozon; underlying business conflicts remain blocked. The validation write-up and sanitized API/parser summaries distinguish environment credentials from the installed seller and do not attribute the screenshot's rows to an unverified dataset.
